## Что реализовано

**Неавторизованный пользователь (гость)**

* просмотр каталога без фильтрации, сортировки и поиска;
* карточка товара: фото (или заглушка `picture.png`), «Производство | Наименование»,
  категория, количество пар с признаком «много/мало», состав, цена со скидкой;
* подсветка карточки цветом `#FF8080`, если остаток по всем размерам не больше трёх пар.

**Авторизованный пользователь**

* вход по логину (пароль не требуется);
* поиск по наименованию, описанию и составу, фильтр по категории,
  сортировка по цене (по возрастанию и убыванию) — всё в реальном времени;
* добавление товара в заказ с выбором размера, изменение количества, удаление позиций;
* оформление заказа: заказ сохраняется за текущим пользователем.

**Менеджер** — дополнительно список заказов с составом и удаление заказов,
выбор клиента при оформлении.

**Администратор** — дополнительно редактирование заказа (клиент, состав, количество).

## Технологии

* C# / .NET 8, **WPF** (`net8.0-windows`), MySqlConnector 2.4.0;
* MySQL 8.0, схема `isp-45_dolgih_ka_chudo_obuv`;
* третья нормальная форма, первичные и внешние ключи, ограничения CHECK и UNIQUE;
* отдельный репозиторий модульных тестов на pytest (задание 5).

## Запуск

Требуется Windows 10/11, .NET 8 Desktop Runtime и доступ к серверу MySQL.

1. Создать схему и загрузить данные:

```
mysql -h 85.236.189.123 -P 13306 -u isp-45_dolgih_ka -p < db/01_schema.sql
mysql -h 85.236.189.123 -P 13306 -u isp-45_dolgih_ka -p < db/02_data.sql
mysql -h 85.236.189.123 -P 13306 -u isp-45_dolgih_ka -p < db/03_verify.sql
```

2. В папке `app/ChudoObuv` скопировать `connection.sample.json` в `connection.json`
и указать параметры своего сервера (файл `connection.json` в репозиторий не входит).

3. Собрать и запустить:

```
cd app/ChudoObuv
dotnet restore
dotnet run
```

Готовый исполняемый файл поставляется вместе с папками `Images` и `Resources`
рядом с `ChudoObuv.exe`.

## Правила расчёта

| Правило | Значение | Где реализовано |
| --- | --- | --- |
| Скидка | 25 %, если в предыдущем календарном месяце заказов товара не было | `Logic/PriceCalculator.cs`, SQL-признак в `DataService.GetProducts` |
| Отображение скидки | над новой ценой зачёркнута старая | `Pages/CatalogPage.xaml` |
| «много / мало» | больше 5 пар — «много», иначе «мало» | `PriceCalculator.GetQuantityLabel` |
| Подсветка | остаток не больше 3 пар — фон `#FF8080` | `PriceCalculator.IsLowStock`, триггер в XAML |
| Итог заказа | сумма количества на цену позиции, округление до копеек | `Models/CartLine.Sum` |

Цвета и шрифт — по руководству по стилю: Calibri, `#FFFFFF`, `#D2F6E7`, `#70B2AF`,
подсветка `#FF8080`.

## Схема базы данных

| Таблица | Назначение |
| --- | --- |
| `roles` | роли пользователей |
| `categories` | категории товаров |
| `subcategories` | подкатегории товаров |
| `manufacturers` | производители |
| `sizes` | размерный ряд |
| `users` | пользователи системы (вход по логину) |
| `products` | товары |
| `stock_items` | товарные позиции (модель + размер + количество) |
| `orders` | заказы |
| `order_items` | строки заказов |

Представления `v_products`, `v_orders`, `v_order_items` используются приложением.

Состав данных: 20 пользователей, 31 товар, 35 размеров, 92 товарные позиции
(1274 пары), 10 заказов и 30 строк заказов.

Подробная схема — в файле [docs/ER-диаграмма.pdf](docs/ER-диаграмма.pdf).
